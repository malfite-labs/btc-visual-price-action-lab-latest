# BTC V3统一行情保护与退出保护规范 V1.0

适用于 BTC V3 的 16 套纸盘策略及以后注册的策略。公共规范负责判定数据与执行是否安全、保存处理证据和恢复进度。仓位方向、入场、止损、止盈、持仓时间、估值和模拟成交价格仍归各策略及现有撮合契约管理。本文为实施和验收基线。

## 1. ABC 基线

| 项目 | 现有行为 | 复用及修正 |
|---|---|---|
| 行情断联 | [market_open_gate_reason](../../backend/market.py#L89) 检查行情来源、最近 288 根有效收盘 K 线连续性、WebSocket 连接与恢复状态、报价时效。市场数据层负责重连和恢复验证。 | 复用同一行情源、验证和故障原因。仅一个普通传输错误不应写成策略永久锁。认证或订阅拒绝、重试耗尽进入独立长期连接诊断，行情确认前继续禁开。 |
| 仓位与止损 | [recovery_blocked](../../backend/recovery_guard.py#L4) 阻断 `RECOVERY_REQUIRED`、`CLOSING` 等不明确状态，核查 A/C 交易 ID、数量、止损和规则元数据。B 的有效待执行止损可隔离处理，避免卡住另外两套。 | 复用核查原则，按策略、账户和仓位归属定位影响范围。其他策略应核对各自账本的等效证据。B 的例外依赖完整待执行记录，不能按策略名放宽。 |
| 止损待执行 | [handle_confirmed_stop / recover_pending_stop](../../backend/execution.py#L108) 区分触发与成交，验证报价，凭确定性事件键恢复待执行止损。 | 优先复用既有事务和幂等接口。E 可继续使用已复用的底层函数。D、G、PA 保留各自账本适配及原始执行语义。 |
| 周期认领 | [市场水位](../../backend/market.py#L110) 与 [业务周期账本](../../backend/scheduler.py#L39) 分别防重复派发及完成。现行运行进程会在前置门禁检查前推进市场水位，短暂断联可能消耗一次派发机会。 | 区分已见、待处理和完成。上一轮准备的同周期重试已在隔离环境验证，但当前运行的 8012 未加载。持久恢复必须以业务账本为准。 |
| 重启恢复 | [报价保护入口](../../backend/app.py#L422) 负责已持仓的止损和目标处理、恢复未完成止损，并在新鲜有效报价及账本检查通过后标记启动保护已核对。 | 加载持仓和待执行退出，核对仓位与账本，先恢复退出再允许新增。空仓且无未决意图时允许正常恢复。各策略的恢复状态按实际证据判断。 |

## 2. 公共状态及最低接口

| 分类 | 触发 | 恢复 |
|---|---|---|
| 就绪 | 行情、周期和本策略新开仓所需证据齐备。 | 继续处理新周期或事件。 |
| 行情暂停 | 短暂断联、过期或无效报价、收盘数据待确认。 | 沿用现有重连，验证行情来源、时间戳、价差及 K 线连续性，重查当前策略状态后自动解除。暂停期间已有有效报价仍可进入保护退出路径。 |
| 持仓缺口待核对 | 带仓跨过一个或多个未完成周期，或特定适配器发现缺少保护行情证据。 | 核对交易归属、仓位数量、原止损止盈、持仓时限及退出回执。证据足以排除漏退出，且满足原适配器核对条件时，可完成现有恢复流程。缺口可能触发退出时保持阻断。 |
| 账本保护待核对 | 未决退出、持仓或成交不一致、配对失配、调度持久锁、其他未知执行结果。 | 先核对事务记录和关联交易。能通过原有持久幂等机制明确恢复的待执行退出可自动处理。其余继续阻断，由运维按证据处置。 |
| 人工暂停 | 用户暂停新增开仓。 | 仅由有权限的人工恢复。行情正常或进程重启均不能解除暂停。已有持仓的退出保护继续运行。 |

状态须附机器原因码、检查时间、最后确认周期或事件时间、最后完成周期或事件 ID，以及最近一次成功保护核对时间。适配器提供三项能力即可接入：输出上述证据、核对当前仓位及未决退出、报告既有幂等执行结果。优先由现有状态、审计和账本提供证据。第一阶段无需建新数据库、行情客户端或事件总线。行情健康与持仓恢复须分别判定，避免共享行情恢复顺手解除策略保护。

## 3. 周期与退出契约

- 周期使用策略 ID、15 分钟收盘时间组成去重身份。只处理来源正确、实际已收盘的 K 线。一次周期的决策、成交和完成证据应可关联。无信号也记录完成。前置门禁拒绝记为待处理或阻断，保留最后实际完成时间。
- 当前有效周期内，只有明确未执行、未产生未知成交、并完成最新行情及持仓核对的事件才可重试。现有有效期至下一根 15 分钟 K 线收盘。过期周期可以核对及记录缺口，禁止借此补开历史仓位。进程重启按已完成和待恢复记录继续，避免重复认领。
- G 保留 C 成交事件触发，使用源成交 ID 去重。G 的同步时间和 15 分钟周期时间分别呈现。原始事件已拒绝、过期或仓位配对不确定时，禁止自动重放补开。
- 退出由原策略计算，公共保护只验证退出事件、交易 ID、方向、剩余数量、可用报价和原撮合契约。已确认触发的待执行退出及其原因持久化，按原有规则恢复。重启后先查询已落账或仍待执行，再决定下一步。账本已有同一退出回执时直接复用；状态未知时暂停新增开仓并对账。
- 每笔退出用稳定的策略、账户、关联交易、退出事件身份去重，保留部分退出的分次身份。用现有账本事务提交结果及位置状态。缺少报价或退出证据时保留原止损及剩余数量，避免凭 OHLC 推断逐笔成交价，或用新的进程时间覆盖历史触发时间。

## 5. 新策略启用检查

1. 注册时声明策略、账户、账本归属、允许的市场、触发类型、预期周期或事件流，以及入场与退出的优先顺序。
2. 静态和隔离测试证明入场使用共享健康证据，拒绝来源错误、过期、不连续或未经确认的数据。人工暂停只阻止新增风险。
3. 验证可读取持仓和退出证据，可恢复并核对已提交、已触发但未完成的退出。保护退出调用只依照原有价格及数量契约。
4. 验证无信号完成、重复周期、断联恢复、过期拒绝、持仓缺口、重复退出、部分退出、重启和状态未知等场景。每项提供可核验原因码和关联 ID。
5. 启用前以只读方式确认当前行情、当前持仓、未决退出、历史游标和人工暂停状态。关系无法唯一确定时保持停用。默认从有效新周期或新事件开始。

### 本轮兼容性证据

- 扩展基线回归使用临时数据库，结果为 205 项通过、8 项失败，另有 10 个子测试通过。五项 D 用例单独重跑通过，整组顺序兼容性仍待核对。

- 还观察到旧 Alpaca 恢复测试调用其适配器未提供的方法，以及一项历史对照报告测试缺少固定输入文件。上述结果不能代替公共适配代码实施后的全量验收。
- 本轮只交付规范和兼容性证据。正式策略、撮合和执行代码未修改，8012、5175 及 Demo 后台均未重启。
