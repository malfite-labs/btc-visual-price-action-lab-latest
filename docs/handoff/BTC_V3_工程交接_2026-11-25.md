# BTC V3 系统工程交接

## 01. 项目概述

BTC Paper Lab V3 在 Windows 本地运行 BTCUSDT 纸盘研究、视觉复盘与 Binance Demo 定额跟单。现有模拟撮合、正式和影子研究账户、策略池、桌面控制台与 Demo 成交链继续使用；真实资金下单关闭。V2 历史资料可能指向 8011，当前 V3 使用 8012，桌面入口统一为「实盘跟单」。定比、全部策略跟单覆盖和统一保护全面实施尚未完成。

## 02. 架构与入口

- 正式目录为 `C:\Users\admin\Documents\量化升级版\btc-paper-lab-v3\windows-binance-deploy`。隔离开发副本只作参考。GitHub 工作树是独立源码副本。
- `backend/app.py` 由 Uvicorn 监听 127.0.0.1:8012。`backend/market.py` 负责行情输入；`backend/rule_cycle.py`、策略池和各专用调度执行纸盘周期。策略版本、模拟撮合和账户依旧以正式库为准。
- `frontend/` 是 React/Vite 5175 前端。原生桌面由 `启动纸盘控制台.cmd` 和 `scripts/local_dashboard.py` 进入；K 线由 `scripts/kline_window.py`、`tools/kline-host/` 与 `frontend/src/KlineWindow.tsx` 显示。
- 跟单入口是 `scripts/live_copy_window.py`。调用链为 `live_copy_service.py → live_copy_v2.py` 事件解析与消费，`live_copy_follow.py → live_c_demo_executor.py → live_c_demo_exchange.py` 执行与回执。SQLite 计划、执行收件箱和成交关联可独立核对。

## 04. 行情与统一保护

WebSocket 提供 Binance 流式行情；HTTP 用于补充或核查报价及历史 K 线。通过闭合 K 线、连续性、来源及报价新鲜度检查后，才进入可执行周期。调度依据周期键、账本和持仓核对恢复，不从历史周期补开仓。ABC 共享行情与恢复门禁，已针对仍有效且未执行的周期调整重试；D 保留独立报价锁，PA 的缺口保护需先对账，E 保留原状态和结构退出，G 依赖原始 C 交易关联。详见 [统一行情保护与退出保护规范 V1.0](../spec/BTC%20V3统一行情保护与退出保护规范V1.0.md)。该规范已写入仓库，16 套策略尚未全部迁移。

## 05. Binance Demo 定额跟单

- 只读消费确认纸盘成交，事件含策略、成交 ID、纸盘交易 ID、方向、动作、数量及时间。首次启用保存游标，历史观测与 DRY_RUN 计划永不补发。相同账户与交易对仅一个活动执行器，账本按配置 ID 隔离；退出只处理原关联仓位。
- 固定保证金结合实际报价、可用余额、预算、杠杆和交易所数量规格向下取整。开仓保留 60 秒时效门禁、暂停和对账保护。HEDGE 以 positionSide 区分 LONG/SHORT。DPAPI Demo 凭据与生产隔离。
- FOLLOW_PAPER 默认不挂独立 Algo 单；按有效选填值增加独立止盈或止损。退出仍跟随纸盘确认成交。成交与手续费来自实际回执；确定性 client ID、独立账本与账户锁处理幂等。未知提交先按 client ID 查证。
- 网络故障触发限速重试、暂停开仓和恢复前对账；人工暂停保持其语义。安全停止前要核对交易、未决委托和敞口。排队切换由桌面窗口推进，完全退出桌面后等待重新打开。队列存在时才显示取消。
- 明细按配置区分纸盘触发和 Demo 真实成交；K 线只标记真实成交，区分 Demo 与生产。可跟单的 11 套为 A/B/C/G、PA-01～06、PA-08，其中 PA-05 为隔离适配通过。D/E/PA-07/09/10 以实际界面适配门禁为准。
- 历史实证示例：11 月 25 日 C 15:45 原开空早于 16:12 启用，16:31 平空无关联可退出。16:45 新开多有实际 Demo 回执。提交中省略账户、订单及配置标识。

## 06. 数据与安全

| 存储 | 用途与保护 |
|---|---|
| `data/paper.sqlite3` | ABC 正式模拟账户及交易；独立核对影子模式及账户标识，禁止覆盖或重置 |
| `data/strategy-pool.sqlite3`、`strategy-control.sqlite3` | PA 运行、控制及周期状态；保留账本、启用状态和 WAL 一致性 |
| `data/d/`、`data/e/`、`data/g/`、`data/pa-v1-extensions/` | 专用及扩展策略运行数据；按实际配置核对路径和关联 |

| 用户本地跟单目录 | 配置、归档、队列、执行收件箱、成交账本和账户锁；用配置 ID、纸盘交易 ID 和执行 ID 对账 |
| `.backups/` | 既有本地回滚材料，先核对 SHA 与时间；账本备份只用于隔离检验 |
| Windows DPAPI 与真实环境文件 | 本机保管，凭据、载荷、运行账户配置全不进入仓库 |

## 07. Windows 部署与运维

本机后端使用 Python 3.12.11，依赖见 `pyproject.toml`；前端依赖见 `frontend/package-lock.json`，在隔离目录执行 `npm ci`、`npm run build`。Windows 原生 K 线需要 WebView2。查看 `scripts/start_backend.ps1`、`scripts/start_frontend.ps1` 和 `scripts/launch_v3.ps1` 的当前参数与防重复启动逻辑。Demo 由桌面的明确授权动作启动，通过安全停止操作退出，持仓未清时继续管理。

- 只读检查 `Get-NetTCPConnection -LocalPort 8012,5175 -State Listen`，再核对进程命令与代码目录；访问 `/api/v1/health`、`/api/v1/system/status`、`/api/v1/strategy-pool`、`/api/v1/d/status` 和 `/api/v1/g-mirror/status`。
- 任何授权重启前，备份当前源码和账本一致性材料，记录仓位、止损、周期及 Demo PID；确认唯一行情连接和调度。启动后先对账、验证持仓及保护连续，再看自然周期。服务异常先看本地日志、跟单状态及独立 SQLite；保留未知订单和保护，禁止盲目重发。
